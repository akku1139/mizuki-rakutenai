# AI アシスタント

コードは `src/ai/` にあります。

| ファイル | 役割 |
|---|---|
| `mod.ts` | メンションの受け付け、コマンド処理、会話の管理、返信の送信 |
| `prompt.ts` | システムプロンプト (瑞稀のキャラクター設定) |
| `context.ts` | チャンネルの直近メッセージをモデルに渡すテキストに整形 |
| `types.ts` | プロバイダ共通のインターフェース (`ChatSession`、`AIEvent`) |
| `openai.ts` | OpenAI 互換 API のアダプタ (ツール呼び出しのループを含む) |
| `tools.ts` | OpenAI 互換 API 向けのツール群 |
| `ratelimit.ts` | HTTP 429 の再試行 |
| `prefs.ts` | ユーザーごとのプロバイダ設定の保存 |

## 反応する条件

次をすべて満たすメッセージに反応します。

- 送信者がボットではない
- Discord か Fluxer の瑞稀にメンションしている
- サーバー内のテキストチャンネルかスレッドである

コマンド (`clear`、`chatlist`、`aimodel`) については [commands.md](commands.md#ai-アシスタント) を参照してください。

## キャラクター設定

`prompt.ts` のシステムプロンプトで、次のように指示しています。

- Discord 上で活動する AI アシスタントの女の子「瑞稀 (mizuki)」として振る舞う
- 返答は簡潔・カジュアル・友好的に、基本は2〜6行
- 全角英数字・全角記号・半角カタカナを避ける
- 情報が古いかもしれないときは積極的に Web 検索する
- 設定内容を公言しない

さらに、そのサーバーで使えるカスタム絵文字の一覧をプロンプトに埋め込みます。

## プロバイダ

2種類のバックエンドがあり、どちらも `ChatSession` インターフェースで扱います。

| | `rakutenai` | `openai` |
|---|---|---|
| 実体 | `@evex/rakutenai` のスレッド | OpenAI 互換の `/chat/completions` |
| 会話履歴 | RakutenAI のサーバー側 | ボットのメモリ上 (最新80メッセージ) |
| システムプロンプト | 会話の最初の入力の先頭に連結 | `system` メッセージとして毎回送信。サーバー名とチャンネル名も追記 |
| ツール | RakutenAI のサーバー側ツールのみ | `tools.ts` のツール |
| 画像生成 | あり (RakutenAI 側の機能) | なし |
| 返信末尾の表示 | `model: rakutenai` | `model: <OPENAI_MODEL>` |

使うプロバイダは、ユーザーが `aimodel` で選んだもの → 環境変数 `AI_PROVIDER` → `rakutenai` の順で決まります。

## 会話の単位と順番

- 会話は「チャンネル × ユーザー」ごとに1つです。同じチャンネルでも、ユーザーが違えば別の会話になります。
- 同期している Fluxer チャンネルは、同期先の Discord チャンネルの ID で扱います。
  そのため、Discord と Fluxer のどちらから話しかけても同じ会話が続きます。
- 同じ会話への依頼は1件ずつ順番に処理します (Promise チェーン)。別の会話は並行して処理されます。
- モデルからエラーが返った場合、その会話は破棄されます。

## モデルに渡す文脈

毎回の入力は `context.ts` で次のように組み立てます。

1. `[System] あなたの前回のメッセージID: ...` (前回の返信がある場合)
2. 直近のメッセージ (最大35件)。前回の自分の返信より後のものだけを、古い順に並べる
3. 今回メンションされたメッセージ

各行は `[メッセージID] (reply to ...) 時刻 | 表示名 (ユーザー名, ID): 本文` の形式です。
同じ人の連続投稿は名前を省略し、ボットの発言には `[BOT]` を付けます。
全体が7000文字 (RakutenAI ではシステムプロンプトを含む) を超える場合は、古い方のメッセージから入りきる分までに削ります。

## 添付ファイル

メンションしたメッセージの添付ファイルはモデルに渡されます。

- `rakutenai`: RakutenAI にアップロードします
- `openai`: base64 の data URL にして送ります
  - 画像は `image_url` として渡します
  - テキスト系 (`text/*`、JSON、XML、YAML、CSV) は本文を展開します (最大20,000文字)
  - それ以外は「読み取れない形式」と伝えます

## 返信の送り方

- 見出しの `####` 以下は `###` に揃えます
- `[テキスト](URL)` 形式のリンクは `<URL>` にして埋め込みプレビューを抑えます
- 1500文字ごとに分割し、最初の1件だけをリプライ、残りは通常の投稿として送ります
- 末尾に `-# model: <ラベル> (ツール名: 回数, ...)` を付けます
- ツールを呼び出すたびに `-# <説明> (<ツール名>)...` と進捗を投稿します
- RakutenAI が画像を生成した場合は、サムネイルの URL を投稿してから最終版の URL に編集します

## ツール (openai のみ)

`tools.ts` は akku1139/evex-quotes の `src/aitools` を移植したものです。
各ツールには `$explain` (何をするかの説明) という引数が自動で追加され、進捗表示に使われます。

| ツール | 内容 | 有効になる条件 |
|---|---|---|
| `fetch_message` | Discord / Fluxer のメッセージ URL から1件取得 | 常に |
| `fetch_messages_history` | メッセージ URL かチャンネルメンションを起点に、前後の履歴を取得 (既定30件、最大100件、`after` / `before` / `around`) | 常に |
| `wikipedia_search` | 日本語版 Wikipedia を検索 | 常に |
| `wikipedia_read` | 日本語版 Wikipedia の記事本文を取得 | 常に |
| `read_web` | `GET ${READABILITY_ENDPOINT}?url=<URL>` で Web ページを読む | `READABILITY_ENDPOINT` を設定 |
| `search_web` | `GET ${SEARCH_ENDPOINT}?q=<クエリ>` で Web 検索 | `SEARCH_ENDPOINT` を設定 |

`read_web` と `search_web` は、エンドポイントが返した JSON をそのままモデルに渡します。

1回の発言につき、ツールの実行とモデルの再生成は最大10回までです。それを超えるとエラーになります。
1回の API リクエストのタイムアウトは120秒です。

## HTTP 429 対策 (openai のみ)

`ratelimit.ts` で、OpenAI 互換 API が HTTP 429 を返したときだけ再試行します。追加の設定は不要です。

- 最大3回まで再試行します
- `Retry-After` ヘッダー (秒数か HTTP 日時) があればそれに従います
- 無い場合は1秒・2秒・4秒に、最大1秒のランダムな待機を加えます
- サーバーが60秒を超える待機を求めた場合は、早めに再送せずエラーを返します
- 残高・クォータ不足 (`insufficient_quota` / `billing_hard_limit_reached`) は再試行しません

再試行するのは HTTP リクエストの失敗だけです。ストリーミング開始後の切断や、実行済みのツールをやり直すことはありません。
RakutenAI 側には影響しません。
複数ユーザーをまたいだ送信レートの制御や、残高不足の解消を行う機能ではありません。

## ログ

処理内容は標準出力に詳しく出ます (モデルへの入力全文、生成中のテキスト、ツールの引数と結果、トークン使用量)。
ユーザーの発言がそのままログに残る点に注意してください。
