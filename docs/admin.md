# 管理パネルとバックグラウンドジョブ

`src/admin/` の小さな HTTP サーバーで、bot の状態を見たりジョブを発行したりします。
Node の組み込み `http` だけで動き、追加の依存はありません。

## 起動

`data/config.json` の `admin` で設定します。

```json
{ "admin": { "port": 8080, "token": "…", "jobConcurrency": 1 } }
```

- `port`: 待ち受けポート (既定 8080)。LAN 向けで、外部公開は想定していません
- `token`: 設定すると `Authorization: Bearer <token>` が必要になります
- `jobConcurrency`: 同時に走らせるジョブの本数 (既定 1)

パネルは `http://<host>:8080/` で開きます。トークンを設定した場合は画面の入力欄に入れてください
(`localStorage` に保存されます)。

## タブ

| タブ | 内容 |
|---|---|
| 状態 | AI の待ち/実行中、会話セッションの一覧、進行中の安価 |
| 同期 | Discord ⇔ Fluxer の同期ペア |
| 設定 | ユーザーごとの AI プロバイダ |
| ログ | 標準出力に出たログのリングバッファ (最新 500 件) |
| チャンネル | チャンネル一覧と、AI が反応しないチャンネルのブラックリスト |
| MCP | MCP サーバーの追加・接続・OAuth・削除 |
| ジョブ | バックグラウンドジョブの発行・状態・中断・結果 |

## バックグラウンドジョブ

**Discord にメッセージを送らずに**エージェントループを回します。出力は捨てずにジョブへ記録し、
パネルから読めます。夜間にまとめて記憶を作る、といった用途を想定しています。

| 種類 | 内容 |
|---|---|
| `agent` | `prompt` をそのまま指示として実行する。`channelId` を添えると、そのチャンネルの直近ログ (`limit` 件、既定 100) を指示のあとに付ける |
| `index` | `channelId` の直近ログを読み、記憶に残すべき事実を `memory` ツールで保存させる。`channelId` は必須 |

指定できるもの:

| フィールド | 内容 |
|---|---|
| `type` | `agent` / `index` |
| `provider` | `openai` / `rakutenai`。省略すると既定プロバイダ (`ai.defaultProvider`) |
| `channelId` | 対象チャンネル (`agent` では任意、`index` では必須) |
| `limit` | 読む件数 (1〜200、既定 100) |
| `prompt` | `agent` の指示文 (8,000 文字まで) |

### 仕組み

- ループは Discord の応答と共通です (`src/ai/agent.ts`)。`runAgent` がイベントを流し、
  本文・使用量・ツール回数・エラーを集めます。Discord 側は受け取ったイベントを投稿に変え、
  ジョブは記録に変えるだけで、モデルの回し方は 1 か所しかありません
- ジョブは**1 本ずつ順番**に走ります (同時に走るとモデルの枠と記憶の書き込みがぶつかるため)。
  `admin.jobConcurrency` で増やせますが、増やすと `data/memory` の書き込みが競合しえます
- 実行中のジョブは**中断**できます。`AbortSignal` でループを抜け、ストリームを閉じます
- 記録するもの: 状態 (queued / running / done / error / cancelled)、開始・終了時刻、結果 (20,000 文字まで)、
  使用トークン、ツール名ごとの回数、イベント (ツール呼び出し・エラー・ログ。1 ジョブ 300 件まで)
- ジョブは最新 100 件まで保持し、終わったものから消えます (パネルの「終了したジョブを消す」でも消せます)

### API

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/jobs` | 実行中・待ち・同時実行数と一覧 |
| GET | `/api/jobs?id=job-1` | 1 件の詳細 (イベント込み) |
| POST | `/api/jobs` | 発行 (`{ "type": "agent", "prompt": "…" }`) |
| POST | `/api/jobs/cancel` | 中断 (`{ "id": "job-1" }`) |
| POST | `/api/jobs/clear` | 終わったジョブを消す |

## 注意

- パネルは bot と同じプロセスで動きます。ジョブが重いと応答が遅くなります
- `index` はモデルに記憶を書かせるので、`src/memory/` の記憶が有効なプロバイダ (`openai`) で使ってください
- bot の再起動で、実行中・待機中のジョブは消えます (永続化していません)
